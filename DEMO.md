# Classroom demonstration — approximately 5 minutes

Start `./run.sh` before presenting and open http://127.0.0.1:8765. The prepared app does not need internet. Keep the server terminal open.

1. **Show a real prediction.** On Predict, explain the eight inputs, the guided shape selection, and separate heating/cooling targets. The default is held-out record 2. Change glazing from 0% to 25%, click Run predictions, and compare all three algorithms. Open the simulated reference and identify development/test membership. Explain that loads are in original dataset units.
2. **Compare alternatives.** Open Compare Designs. The defaults differ in glazing, 25% versus 40%, while sharing the other inputs. Run the comparison, explain B minus A, and export the CSV. The displayed simulated heating loads are equal; model predictions need not preserve that tie.
3. **Explain the research result.** Open Study Results. RF wins the random-holdout comparison, while MLR wins on excluded shapes. Switch between heating and cooling. Explain that validation context changes model suitability. Show RF feature reliance and the matched glazing example, whose saved predictions excluded the entire shape.
4. **Show your own-data workflow.** Open Test Your Dataset and select **Try simulated example**. Explicitly identify these as simulated workflow records. Alternatively, drop your own CSV/Excel file into the upload area and select Upload & inspect. Follow the three-step guide and review the source preview and eight required input mappings. Validate and run with no comparability declaration: the result is predictions only. For reference scoring, open **Add reference loads for error scores**, review the reference mappings and source definitions, confirm comparability, validate again, and run. Show metrics, RF prediction/residual plots, CSV/JSON exports, and reopening the saved evaluation.
5. **State the boundary.** Explain that actual building data needs matching architectural definitions, category codes, scales, and comparable load references. The app flags unfamiliar geometry, does not retrain on test data, and does not turn electricity bills alone into a validated building-energy model.
